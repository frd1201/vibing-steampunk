# `vsp document` — generated documentation, and pushing it into SAP

**Status:** backlog. Routing settled by measurement on 2026-08-24; nothing built.

The idea is ZXRAY's, and it is a good one: generate documentation for an object
and **push it down into SAP's own documentation store**, so it shows up where an
ABAP developer already looks — F1, SE61, the object's own documentation tab —
rather than in a file nobody opens. ZXRAY did it with a markdown→ITF converter
written in ABAP. It could not do packages. We should do packages.

Nothing here is built. What *is* established is the routing, and it cost four
probes, so it is written down rather than left to be re-derived.

## The format

SAP object documentation lives in `DOKHL` (headers) and `DOKTL` (lines), keyed
by `ID` + `OBJECT` + `LANGU` + `TYP` + `DOKVERSION`. `DOKTL` carries the two
columns that matter:

| column | what it is |
|---|---|
| `DOKFORMAT` | the ITF tag — `AS` heading, `U1`/`U2` lists, `*` body, `/` continuation |
| `DOKTEXT` | the line, 132 characters |

That is SAPscript ITF, the same shape SO10 texts use. `ID` selects the kind:
`RE` for reports, `FU` for function modules, `CL`/`CO` for classes, `TX` for
general texts. A markdown→ITF converter is the small half of this job; it is
line-oriented, the tag vocabulary is short, and it is pure and testable with no
system anywhere near it.

## Routing — measured, not assumed

**Reading is Class A: plain ADT, works today.** Both tables answer free SQL.
Verified on a4h:

```
vsp query DOKHL --where "ID = 'RE' AND OBJECT LIKE 'RSUSR%'" \
                --fields "ID,OBJECT,LANGU,TYP,DOKVERSION"
vsp query DOKTL --top 3      # DOKFORMAT + DOKTEXT come back
```

Neither is a cluster, so nothing here is blocked the way `BALDAT` is.

**Writing is Class D: it needs ABAP on the server.** Both other routes are
closed, and each was checked rather than reasoned about:

- **ADT exposes no documentation resource.** Seven plausible paths all answer
  404: `/sap/bc/adt/docu`, `/docu/abap`, `/documentation`,
  `/knowledgetransfer/documents`, `/abapdocu`, and `…/{object}/documentation`
  under both programs and classes. The discovery document mentions `docu` twice
  and neither is this: an ODA value help (`aps/com/sod1/docuprogramobjtype`) and
  BDEF *language* documentation (`behaviordefinitions/docu/langu`, read-only,
  `text/plain`).
- **No `DOCU_*` function module is remote-enabled.** `TFDIR.FMODE` is empty for
  every one of `DOCU_READ`, `DOCU_UPD`, `DOCU_UPDATE`, `DOCU_DEL`, `DOCU_INIT`,
  `DOCU_COPY` and the rest. Control: `RFC_READ_LEGACY_DEST_USE` shows `R`, so
  the column means what it should and the emptiness is real.

  **This is the `BAL_DB_SEARCH` shape again**, and it is worth naming as a
  pattern: the blocker is not the transport. Classic RFC, SOAP-RFC and the
  WebSocket tunnel are all equally useless here, because the modules are simply
  not callable from outside. Reaching for a different transport is the wrong
  move and it is the move that looks obvious.

So the write half joins stateful RFC and full-coverage git as the **third**
member of Class D — and the capability map in
[the article](../articles/2026-08-24-adt-capability-map.md) says "exactly two",
which will need correcting when this is built.

## Shape, if it gets built

Three pieces, and the first two are worth having on their own:

1. **`vsp document <object>` — generate.** Markdown, from what vsp already
   knows: signature and sections, callers and callees, package boundary
   direction, effects and LUW class, transport history. Read-only, no system
   changes, useful the day it lands. **Packages included** — that is the gap in
   the original, and `AcquirePackageScope` already resolves the hierarchy.
2. **`--format itf` — convert.** Pure markdown→ITF. No SAP. Table-driven tests
   over the tag vocabulary, and a round trip: ITF read back from `DOKTL` on a
   documented standard object must survive being parsed and re-emitted.
3. **`--push` — store.** Needs a receiver: one class over `DOCU_UPD`, in
   `ZADT_VSP`. Small — the ABAP side is a wrapper, not logic.

Steps 1 and 2 need nothing installed and can ship first. Step 3 should not be
started before someone decides Class D is allowed to grow, because the whole
argument of the routing table is that it stays small.

## Two things not to relearn

- `DOCU_*` is not remote-enabled. Checked 2026-08-24 on 7.58. Do not go looking
  for a transport that reaches it.
- ADT has no documentation resource. Seven paths, all 404, discovery clean.
